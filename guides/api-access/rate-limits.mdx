Brandstack rate limits API requests to keep the service fast and reliable for everyone. Each API key is allowed up to 60 requests per minute. If you exceed that limit, the API returns a `429 Too Many Requests` response with a `Retry-After` header that tells you how many seconds to wait before retrying.

## Current limits

| Limit | Value |
| --- | --- |
| Requests per minute | 60 per API key |
| Window type | Sliding window |
| Throttled response | HTTP 429 \+ `Retry-After: <seconds>` header |

## 429 response example

If you send too many requests in a short window, you will see a response like this:

```http Response
HTTP/1.1 429 Too Many Requests
Content-Type: application/json
Retry-After: 45

{
  "error": {
    "code": "rate_limit_exceeded",
    "message": "You have exceeded the maximum number of requests per minute. Retry after 45 seconds."
  }
}
```

Your integration should read the `Retry-After` header and pause before sending the next request. Polling the API during the backoff window will only extend the wait time.

## Error-handling pattern

```python Python example
import requests
import time

headers = {"Authorization": "Bearer <token>"}
response = requests.get("https://api.brandstack.com/v1/orders", headers=headers)

if response.status_code == 429:
    retry_after = int(response.headers.get("Retry-After", 60))
    time.sleep(retry_after)
    response = requests.get("https://api.brandstack.com/v1/orders", headers=headers)
```

## How to stay within limits

- Batch date range queries via the `/metrics` endpoint instead of looping one day at a time.
- Cache responses when data freshness is not critical.
- Use cursor pagination where available instead of requesting the same large page repeatedly.

<Tip>
  If you need daily trends, call `/metrics` once with a `from` and `to` range and the `dimension` parameter set to `day`. This returns all daily values in a single request instead of forcing you to loop per day.
</Tip>
